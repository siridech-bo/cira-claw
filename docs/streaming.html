Streaming Modes

CiRA CLAW supports three video streaming modes, each with different latency and compatibility characteristics. The dashboard automatically selects the best mode based on availability.

WebRTC (go2rtc)

~100ms latency

Ultra-low latency peer-to-peer streaming via go2rtc server.

  • Real-time monitoring
  • Hardware acceleration
  • Adaptive bitrate
  • STUN/TURN support
  • Requires go2rtc binary

MJPEG

~500ms latency

Motion JPEG stream over HTTP. Widely compatible fallback.

  • No special setup required
  • Works in all browsers
  • Auto-reconnection
  • Detection overlays
  • Higher bandwidth usage

Polling

~1s latency

Single frame requests. Last resort fallback mode.

  • Maximum compatibility
  • Works through proxies
  • Lowest CPU usage
  • Canvas-based rendering
  • Choppy video

Stream Watchdog

The dashboard monitors stream health and automatically triggers reconnection if no frames are received for 5 seconds. This handles network glitches and device restarts gracefully.

go2rtc Configuration

go2rtc provides WebRTC streaming with STUN/TURN support for NAT traversal.

cira.json Configuration

{ "go2rtc": { "enabled": true, "apiPort": 1984, "webrtcPort": 8555, "stunServers": [ "stun:stun.l.google.com:19302" ] } }

Runtime Stream Endpoints

Each edge device running CiRA Runtime exposes these HTTP endpoints:

Endpoint Type Description
/stream/raw MJPEG Raw camera feed without annotations
/stream/annotated MJPEG Stream with detection bounding boxes and labels
/frame/latest JPEG Single frame for polling mode
/api/detections JSON Current frame's detection results
/api/stats JSON FPS, inference time, model info

Detection Persistence

To reduce bounding box flickering, the runtime implements time-based detection persistence.

How It Works

Detections are held for a configurable duration (default: 150ms) after they disappear from the frame. This creates smoother annotations without the distracting flicker that occurs when objects are briefly undetected between frames.

// Detection persistence configuration DETECTION_HOLD_MS = 150; // Hold annotations for 150ms // Detections are matched by: // - Same class label // - IoU (Intersection over Union) > 0.5

Browser Memory Management

Long-running camera streams can cause browser memory issues. CiRA CLAW implements automatic page reload to prevent OOM crashes.

Scheduled Page Reload

The gateway automatically triggers page reloads every 25 minutes. A warning is sent 30 seconds before reload via WebSocket, allowing the dashboard to show a notification to users.

WebSocket Events

// 30 seconds before reload { "type": "page:reload_warning", "payload": { "secondsUntilReload": 30, "timestamp": 1717000000000 } } // Reload trigger { "type": "page:reload", "payload": { "reason": "scheduled_memory_cleanup", "timestamp": 1717000030000 } }

Usage Example

Here's how to embed a camera stream in your own application:

// 1. Get stream URLs from API const response = await fetch('/api/nodes/jetson-line1/stream'); const { streams, go2rtcEnabled } = await response.json(); // 2. Try WebRTC first (if available) if (go2rtcEnabled && streams.webrtc) { const pc = new RTCPeerConnection({ iceServers: [{ urls: 'stun:stun.l.google.com:19302' }] }); pc.ontrack = (event) => { videoElement.srcObject = event.streams[0]; }; // Negotiate with go2rtc API... } // 3. Fallback to MJPEG else { imgElement.src = streams.mjpeg; } // 4. Ultimate fallback: polling setInterval(() => { imgElement.src = `${streams.mjpeg.replace('/stream/', '/frame/')}?t=${Date.now()}`; }, 1000);
