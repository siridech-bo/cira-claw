Overview

The CiRA CLAW Rule Engine allows you to create JavaScript automation rules that respond to detection events, signals from MQTT/Modbus, and other triggers. Rules are executed in a secure sandbox environment with access to detection data and system context.

JavaScript Sandbox

Rules run in isolated-vm for security. Full ES6 support with controlled API access.

Rule Structure

Every rule must export an evaluate function that receives a context object and returns a result.

// Basic rule structure function evaluate(ctx) { // Access detection data const detections = ctx.detections; const params = ctx.params; // Your logic here... if (someCondition) { return { triggered: true, action: 'alert', data: { /* custom data */ } }; } return { triggered: false }; }

Context Object (ctx)

The context object provides access to all detection data, signals, and configuration.

Detection Data
ctx.detections Array Array of detected objects with label, confidence, bbox
ctx.detections[].label string Class label (e.g., "scratch", "person")
ctx.detections[].confidence number Confidence score (0.0 - 1.0)
ctx.detections[].bbox object Bounding box {x, y, width, height}
Rule Configuration
ctx.params object User-defined parameters from rule config
ctx.nodeId string ID of the node that triggered the rule
ctx.ruleId string ID of the current rule
Signals (Protocol Bridges)
ctx.signal object Current signal values from all sources
ctx.signal.vibration number Vibration sensor value (if available)
ctx.signal.anomaly number Anomaly detection score (if available)
Timing
ctx.timestamp number Unix timestamp of the detection event
ctx.frameNumber number Frame number from the video stream

Return Value

The evaluate function must return an object indicating whether the rule was triggered and what action to take.

// Return when NOT triggered return { triggered: false }; // Return when triggered return { triggered: true, action: 'alert', // Action type data: { // Custom data passed to action count: 5, severity: 'high', message: 'Defects detected!' } };

Action Types

Rules can trigger various actions when conditions are met.

Action Description Data Properties
alert Send alert to dashboard and connected clients message, severity
mqtt_publish Publish message to MQTT topic topic, payload, qos
line_notify Send LINE notification message, imageUrl
modbus_write Write to Modbus register address, value
webhook Call external HTTP endpoint url, method, body

Examples

Defect Count Threshold

Alert when the number of detected defects exceeds a threshold.

function evaluate(ctx) { const defects = ctx.detections.filter(d => d.label === 'scratch'); if (defects.length >= ctx.params.threshold) { return { triggered: true, action: 'alert', data: { count: defects.length, severity: defects.length >= 5 ? 'critical' : 'warning', message: `Detected ${defects.length} defects on ${ctx.nodeId}` } }; } return { triggered: false }; } // Rule params: { threshold: 3 }

MQTT Publish Detection Counts

Publish detection counts to MQTT for external systems.

function evaluate(ctx) { const counts = {}; ctx.detections.forEach(d => { counts[d.label] = (counts[d.label] || 0) + 1; }); return { triggered: true, action: 'mqtt_publish', data: { topic: `cira/${ctx.nodeId}/detections`, payload: JSON.stringify({ timestamp: ctx.timestamp, counts: counts, total: ctx.detections.length }), qos: 1 } }; }

Signal-Based Alert (Vibration + Detection)

Combine vibration sensor data with visual detection for anomaly alerts.

function evaluate(ctx) { const hasVisualAnomaly = ctx.detections.some(d => d.label === 'anomaly' && d.confidence > 0.8 ); const highVibration = ctx.signal?.vibration > ctx.params.vibrationThreshold; // Alert only when both conditions are met if (hasVisualAnomaly && highVibration) { return { triggered: true, action: 'line_notify', data: { message: `ALERT: Anomaly detected on ${ctx.nodeId}\n` + `Vibration: ${ctx.signal.vibration}\n` + `Visual confidence: ${ctx.detections[0].confidence.toFixed(2)}` } }; } return { triggered: false }; } // Rule params: { vibrationThreshold: 50 }

Modbus Register Write

Write detection count to Modbus register for PLC integration.

function evaluate(ctx) { const defectCount = ctx.detections.filter(d => d.label === ctx.params.targetClass ).length; return { triggered: true, action: 'modbus_write', data: { address: ctx.params.registerAddress, value: Math.min(defectCount, 65535) // Clamp to 16-bit } }; } // Rule params: { targetClass: 'scratch', registerAddress: 100 }
